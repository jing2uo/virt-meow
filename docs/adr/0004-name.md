# ADR-0004: The name is virt-meow, the command virt-mm

- Status: accepted
- Date: 2026-11-01

## Context

Its users come from virt-manager, whose window title is "Virtual Machine
Manager" and whose name is long to type. A short command sits well next to
virsh and virt-manager, but as the name people see, in a menu, a window
title, a sentence, an abbreviation reads poorly.

## Decision

The product is **virt-meow**; its command is **virt-mm**, as Visual Studio
Code's is `code` and ripgrep's `rg`. Both are written all lower case, at the
start of a sentence too, as virt-manager is.

- virt-mm is "Virtual Machine Manager" shortened: virt- and mm. The virt-
  prefix follows libvirt's tools (virsh, virt-manager, virt-install,
  virt-viewer).
- It reads as "meow-meow" (喵喵 in Chinese, whose pinyin initials are mm),
  and virt-meow says it outright: easy to remember where virt-mm is easy to
  type. The logo is a cat: the flatpak icon and the page's favicon.

Which of the two a string uses depends on one question: **is it typed into
a terminal as it is, or read or matched by a program?** Then it is
`virt-mm`; otherwise, when it is for people and means "this software", it is
virt-meow.

- virt-meow: the window's title and the Wails application name, the pages'
  `<title>` and brand, the desktop file's `Name=`, the text of the pages
  (Chinese and English) where it speaks of the program, desktop
  notifications, the label of what it keeps in the keychain
  (`virt-meow: …`), sentences in CLI output that speak of the program,
  comments and documentation; also the repository and the Go module
  (`github.com/jing2uo/virt-meow`), named after the product as the
  repository of Visual Studio Code is. A module path is matched by
  programs, but it names where the code lives, not a command.
- virt-mm: the binary, every command and example of one (also inside the
  pages' text: `virt-mm serve --set-password`), the `virt-mm: ` prefix of errors and
  warnings (a command's name, as `grep: `), the environment variables
  `VIRT_MM_*` (`VIRT_MM_CONFIG`, `VIRT_MM_URI`, …), the config directory
  `<UserConfigDir>/virt-mm`, cookies, localStorage keys and DOM event
  names, container images, temporary directories, build outputs, and the
  names virt-meow puts in libvirt and in guests (`virt-mm-tmp-…`,
  cloud-init's instance-id).
- `virt-mm --help` starts with both: `virt-mm - virt-meow on the command
  line: …`. The desktop file's `Exec=` is `virt-mm`; its `Keywords=` has
  both, so a search for either finds it.
- The application ID is `io.github.jing2uo.VirtMeow`: flatpak IDs are best
  kept free of `-` in their components. The Secret Service schema follows
  it: `io.github.jing2uo.VirtMeow.Secret`.

## Consequences

- Every new string, flag, file or identifier is named by the question
  above; a review that finds the wrong one fixes it.
- Renaming either later is a new application ID, config directory and
  keyring schema: installed copies would not carry over.
