# P0: replace virt-manager for daily use

What virt-meow must do before it replaces virt-manager on its author's own
machines. Each milestone ends usable and tested, against libvirtd in a
container (`make e2e`). Each capability lands in the CLI first, then in the
pages ([ADR-0003](../adr/0003-front-ends.md)); [virsh.md](virsh.md) tracks
the CLI against virsh.

## M1: connections, the machine list, power

- Connections: add, remove, list; `qemu:///system`, `qemu:///session`,
  `qemu+ssh://`. Several open at once, each with its state.
- Host keys: unknown key shown with its fingerprint and trusted on the user's
  word; a changed key refused.
- The machine list of each connection: name, state, vCPUs, memory,
  persistent, autostart. Kept current by libvirt's lifecycle events, not by
  polling.
- Power: start, shut down (ACPI), reboot, force off, pause, resume.
- CLI for all of it (`virt-mm conn`, `virt-mm ls`, `virt-mm start` …, `--json`).
- GUI: connections in a sidebar, the list, the power actions, the host-key
  prompt.

## M2: a machine's details

- Overview, read from the domain XML through libvirtxml: OS, firmware, CPU,
  memory, disks, network interfaces, graphics, other devices.
- Live use: CPU, memory, disk and network rates, from
  `ConnectGetAllDomainStats` (one call for every running machine).
- Host overview: CPU, memory, libvirt and QEMU versions.

## M3: consoles

- VNC in the page: noVNC, its WebSocket forwarded by virt-meow over the host's
  SSH connection, or straight to the server locally. Done, with SPICE
  through spice-html5 beside it (ADR-0001): a running machine's Console
  button, or `virt-mm gui console <machine> [spice]`; Ctrl+Alt+Del, VNC
  scaled to fit, full screen.
- Serial console: xterm.js on `virDomainOpenConsole`.
- Send keys (Ctrl+Alt+Del, Ctrl+Alt+F1…), scaling, full screen. Done in
  the page: the screen fits the pane or shows at actual size, the guest's
  resolution can follow it, a menu of the keys the desktop keeps, text
  typed into a guest with no agent, a console in a window (or tab) of
  its own, and the keyboard grabbed for the guest as virt-manager's
  (Ctrl+Alt lets go).
- Measure first: frame rate of a 1080p guest in WebKitGTK, WKWebView and
  WebView2.

## M4: creating machines

Done first, ahead of M2 and M3, because a host with no machines shows
nothing: the form (`virt-mm create`, the GUI's New machine), ISO and image
upload through libvirt's stream, a new qcow2 disk or an existing volume,
bridge or libvirt network, BIOS/UEFI/Secure Boot, TPM, start; and deleting a
machine with its disks. Then a copy of a cloud image grown to size, with
cloud-init (`virt-mm create --image --cloud-init`), and osinfo-db recognising
the ISO or image and proposing the rest (`virt-mm create --os-variant`).

- From an installation ISO or a disk/cloud image in one of the host's storage
  pools, or uploaded to one.
- osinfo-db (the host's own, read over SSH, or the copy virt-meow ships)
  recognises the system and proposes memory, disk, firmware and devices.
- Cloud images get cloud-init (user, SSH key, hostname) as a NoCloud ISO.
- Defaults: KVM when the host has it, virtio devices for guests with drivers,
  UEFI where the system wants it, VNC graphics.

## M5: editing machines

- CPU (count, topology, model), memory, firmware and Secure Boot, boot order,
  disks (add, remove, grow), CD/DVD, network interfaces, video, graphics,
  TPM, sound, RNG, autostart.
- What can change on a running machine changes now; the rest is saved for
  the next start, and the page says which is which.
- The XML editor for everything else; libvirt validates before saving.
  Done first: `virt-mm xml`, `virt-mm edit`, `virt-mm create --print-xml/--xml`,
  and in the GUI a machine's XML and a new machine's before it is created.
- In the CLI: `virt-mm set` (vCPUs, topology, CPU model, firmware, memory,
  autostart, title), `rename`, `define`, `disk`, `cdrom`, `nic`, `boot`,
  `device` (video, graphics, TPM, sound, RNG). Still to do: the GUI's pages
  for all of it.

## M6: snapshots, storage, networks

- Snapshots: create, revert, delete, the tree.
- Storage pools and volumes: create, grow, delete, upload.
- Virtual networks: NAT, routed, isolated, bridge; start, stop, autostart.
- Clone a machine, its disks included.

## After P0

`virt-mm serve` runs the pages in a browser (ADR-0003), with a login and
TLS. Done since: the pages (a machine's details and hardware, snapshots,
storage, networks, monitoring), USB and PCI passthrough from a list of the
host's devices, virtiofs shared folders, an overview of every host with
bulk power actions. Still to come: live migration between connections,
SPICE, packaging for macOS and Windows, then cluster mode.
